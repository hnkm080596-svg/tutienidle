Medium — system-theme.css / SysPanel — the animation-performance claim is internally too strong. The spec says signature effects are limited to transform/opacity/background-position, but the rotating conic-border design explicitly animates --angle inside a conic-gradient. That generally requires repainting the gradient every frame; it is not equivalent to a compositor-only transform. Ten simultaneously visible animated rims plus translucent backdrop-filter panels can become materially expensive, especially inside Electron/browser windows on integrated GPUs. Pin a performance policy: only the focused/primary panel gets the continuously rotating rim; secondary panels use static gradients or infrequent opacity pulses; cap simultaneous scan sweeps; and provide a low-effects class/fallback independently of prefers-reduced-motion. P14 should include a dense screen with all Wave-1 surfaces visible, not isolated component screenshots.
Medium — theme ownership needs an explicit selector/boundary contract, not only “interface vs scene.” The conceptual split is good, but many existing panels compose shared ink-wash primitives, global progress components, and nested common controls. Without a concrete rule, Wave 1 can produce hybrid surfaces where a SysPanel contains InkNineSlice/gold tokens or where globally restyled progress bars change world-owned UI unintentionally. Pin something like: system styling is opt-in through .sys-surface/Sys* primitives; --sys-* tokens never redefine --ink-*/--gold-*; world/Phaser/ink primitives cannot be descendants targeted by broad system selectors; shared components receive an explicit visual variant rather than being globally restyled unless every caller is audited. This makes the “remove one import to revert” claim genuinely enforceable.
Medium — accessibility needs focus-state and background-contrast rules beyond the 4.5:1 text target. Cyan glow aesthetics are vulnerable to three problems: translucent surfaces can lose contrast over bright scene art, glowing borders can obscure native focus indication, and status meaning can become color-only (cyan/violet/warn/danger/success). Add explicit requirements: system panels have a minimum opaque backing/scrim sufficient to preserve contrast regardless of underlying scene; every keyboard-interactive control gets a non-glow-dependent :focus-visible indicator with at least a 2px perceivable outline/offset; danger/success/rarity states retain text/icon/shape cues in addition to hue. Also forbid scanline/flicker overlays from crossing text at an opacity that measurably reduces contrast.
Low — motion policy should distinguish reduced motion from reduced visual effects. prefers-reduced-motion correctly stops sweep/shimmer/flicker/orbit animations, but static scanlines, glow stacks, blur, and high-frequency edge detail can still be visually fatiguing and expensive. Define the reduced-motion state concretely: no flicker, no translating scan sweep, no shimmer, no rotating rim; static corner marks and a single nonanimated border/glow are retained. This avoids each primitive inventing its own interpretation.
Low — typography/font delivery needs a pinned fallback contract. Chakra Petch is suitable visually, but the spec should define the actual font stack and behavior if the webfont fails or is unavailable in packaged/offline Electron builds. Headers/numerals must remain layout-stable and Vietnamese-safe under fallback; do not let missing glyphs silently fall back per-character to a radically different face. A bundled/local font is not required, but the fallback stack should be explicit and P14 should exercise Vietnamese diacritics in representative headers and numeric/stat rows.
The Wave-1 surface selection is otherwise well chosen: HUD, Character, Realm, NodeTree, shared progress, and modal chrome establish the new language across status, progression, and transactional UI without dragging inventory/worker/lore surfaces into the first migration. I would not add scrollbars, rarity mapping, or enter/exit transitions as blockers for this mission; those are better follow-up polish once the base chrome/token system is proven.
