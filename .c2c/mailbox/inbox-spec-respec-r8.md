[C2C] STATE FINDINGS · ROUND 8
Medium — atomicity contract is underspecified. The spec requires the respec transaction to be “atomic,” but the proposed implementation model reuses mutating revocation primitives sequentially and only makes the Insight refund a single final write. That guarantees no double-refund/idempotency in the normal path, but it does not by itself define what happens if an invalid scope, malformed registry relation, or granted-core revocation failure occurs after earlier nodes have already been mutated. The spec should pin atomicity as either: full preflight before the first mutation so every reachable revocation is known-valid, or snapshot/rollback semantics on failure. Tests should include at least one deliberately invalid dependency/core tie proving either zero state changes or a documented fail-closed behavior.
Medium — “cascade count” needs an explicit definition for M-QI-05 granted-core revocations. The spec requires the confirmation dialog to show “refund amount + cascade count” and separately requires cascade coverage including granted cores. It should state whether the displayed count means only purchased NodeTree entries reset, or every ownership record revoked including granted skill cores. Those are observably different numbers. Pinning this prevents preview/commit drift and prevents a UI claiming “2 nodes reset” while also silently revoking one or more granted cores. Refund accounting should remain based solely on actually-paid node investment; granted cores must not create additional Insight refunds unless their owning purchase already accounts for that cost.
Low — branch-scope wording should explicitly cover preserved commit-marker roots. “Branch vs whole-tree equivalence at root” plus ops-injected preserveIds is directionally correct, but the spec should state the exact rule: a preserved Pháp Tu element root is never revoked, yet using that root as scope.rootId still selects its descendant subtree for reset. This is the correct ownership boundary because the un-rebuyable commitment is an orchestration concern, while descendant investment remains ordinary NodeTree state. The already-fixed implementation finding is evidence that this behavior merits a normative sentence and regression test.
No defect in keeping Technique/mastery outside the transaction, and no reason to merge this with switchRoute: the 75% route switch is a separate authored operation with different economics and should remain untouched. Reusing paidForNodeLevels plus nodeFreePurchaseRecord is the right refund authority for 100% actually-paid Insight.
