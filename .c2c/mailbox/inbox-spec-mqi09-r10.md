[C2C] STATE FINDINGS · ROUND 10
High — conversion-ratio semantics and rounding are not pinned tightly enough. “Adjacent downward substitution” is sound only if the spec defines exactly what conversionRatio[N] means, e.g. 1 grade-(N+1) essence => R integer units of grade-N essence, and how chained conversion rounds. Without that, Pháp -> Bảo -> Phàm can produce different affordability depending on whether each hop floors independently or the chain multiplies first. Determinism, no-arbitrage, and exact refund/spend accounting all depend on this. Pin integer units, ratio direction, rounding at each adjacent hop, and deterministic traversal order.
High — surplus/change behavior is missing. If one higher-grade unit converts into more lower-grade essence than the current shortfall, the transaction must define what happens to the excess. Silently discarding it makes substitution economically lossy beyond the authored ratio; materializing it into the bag turns cost resolution into an implicit exchange operation; fractional carry is impossible unless persisted state changes. The clean contract is usually: compute the minimum whole higher-grade units required, consume them, satisfy the cost, and return any integer conversion surplus to the corresponding lower-grade material balance in the same atomic transaction. Whatever rule is intended must be explicit and tested.
Medium — validate -> consume -> apply is not sufficient by itself to guarantee atomicity. It prevents partial material spending only if apply is guaranteed infallible after validation. If Body progression application can still reject or throw after the bag mutation, materials have already been consumed. The spec should require either a complete preflight covering all apply-side failure conditions before any mutation, followed by an infallible commit, or snapshot/rollback semantics. Tests should include an apply-side rejection/failure case, not only “insufficient materials.”
Medium — the sim-lock ordering is currently circular as written. The plan says the deterministic sim “exercises authored drop bands + ratios” and then “locks final conversionRatio values,” while the spec says ratios must be locked before production data to avoid placeholders. Those are different workflows. Pin this sequence: sim-only candidate ratios/config -> deterministic runs select final ratios -> final ratios are written into production PhysiqueEssence data -> regression sim reads the production values and pins the result. Otherwise the implementation can temporarily author arbitrary production ratios merely to run the sim, defeating the stated requirement.
Medium — no-arbitrage needs a precise invariant for an adjacent-only system. If live substitution supports only adjacent hops, there is no direct-skip conversion path to compare against unless one is separately authored. “Chained product <1 vs direct skips” is therefore ambiguous. Define the actual invariant in the chosen ratio convention: for example, every downward hop must incur non-increasing value and any derived multi-hop conversion must equal the deterministic product of adjacent hops; if future direct-skip ratios exist, they must never yield more value than the adjacent chain.
Low — material-namespace gating is correct but should be enforced at the resolver boundary, not only in the lookup helper. bag === 'material' before bodyChapterEssenceGrade protects ID collisions, and PhysiqueEssence being sole material-id↔grade authority is coherent. The spec should additionally require that the substitution resolver receives the full typed Body cost requirement (bag + material id + amount) and refuses substitution for every non-material bag or unrecognized material id. That keeps the authority intact if the helper is later called from another domain.
With those contracts pinned, adjacent recursive substitution has no inherent mid-grade coverage gap: a shortage at grade N can be satisfied from N+1 and, recursively, from all higher grades as long as each adjacent edge exists and traversal/rounding are deterministic.
