[C2C] STATE FINDINGS · ROUND 18
Medium — §4.1.1 / §5 — rim authority is still tied to component mount order rather than visible/active ownership. useSystemRimAuthority() is specified as “registers on mount and unregisters on unmount,” with the top of that stack owning .sys-rim--live. That is insufficient for Vue overlays/drawers that remain mounted while open=false, or for an already-mounted modal that later becomes visible. A hidden primary can remain above the drawer in the stack, and opening an already-mounted modal does not necessarily push it to the top. The contract should register/activate on visible primary state, deactivate when hidden, and promote on each open/activation. For modal surfaces, open must be part of the authority input; for drawers, eligibility should likewise reflect actual visibility. The authority should therefore model an ordered set of currently active rim claimants, not lifetime mount registration. The E2E should include closed-but-mounted → open → close handoff, not only a static count of one.
Low — §2.4.1 conflicts with §2.2.5 and §3's allowed scoped token remaps. The guard says “Each --sys-* token is defined exactly once,” while the spec explicitly permits per-surface --sys-* overrides and says tokens are defined under :root “and scoped remaps where noted.” A legitimate rule such as .sys-tag--danger { --sys-accent: var(--sys-danger) } would violate a literal exactly-once scan. Pin the guard to canonical/root declarations exactly once, while permitting scoped assignments/overrides inside anchored system selectors. Keep the prohibition on defining canonical tokens outside system-theme.css.
Round-15 findings (1) and (3) are otherwise resolved correctly: §2.3 now states the achievable safe-degrade guarantee rather than impossible byte-identical restoration, and §2.4 explicitly separates ordinary selectors from allowlisted at-rules while still policing nested selectors.
The one-live-rim design also now has the right architectural direction—a single shared authority rather than caller convention—but its lifecycle semantics need the visibility fix above before the spec is implementation-safe.
