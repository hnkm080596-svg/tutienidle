## Behavior before -> after

- **ARCH-005 (skill bar invisible in live combat).** Before: `useTurnCombatManual`
  derived `isBattleFighting`/`slots`/`slotList` chained off `battle` — a computed
  that always returns the SAME in-place-mutated TurnBattle reference — so after
  first evaluation Vue cached the projections forever (Edge probe:
  `state:fighting`, `turns:3`, `roots=0`). `TurnOrderStrip.partyMembers`,
  `BattleLogPanel.visible/recentEntries`, and both result panels' `summary`
  had the same shape. After: every one of these computed bodies reads
  `stateVersion.value` directly — the App.vue tick bump invalidates them, same
  contract `useTurnBattleInfo` already documents. No local timers added; no
  reactivity pushed into the domain.
- **ARCH-014 (silent defeat + dead listeners).** Before: the terminal in
  `grantTurnBattleRewards` stamped `battleEndEmitted` for both outcomes but only
  emitted `battle_end` on victory; abandon emitted `defeat` itself outside the
  guard. Natural defeat never reached `battleDefeat` audio,
  `CombatScene.onBattleEnd`, or the PhaserCanvas snapshot-cache clears. After:
  `rewardOps.publishBattleEnd(state)` is the single emit site
  (`grep emit('battle_end'` -> exactly one site); victory and natural defeat
  publish through it inside the once-guard, abandon publishes through
  `emitAbandonEnd()` which shares the same flag (a settle earlier in the frame
  cannot double-emit; a repeated abandon is refused before reaching it).
  Dead listeners retired: `CombatScene.getCombatEventBindings()` no longer
  subscribes `positions`/`cast_start`/`cast_complete`/`player_teleported`
  (verified zero live producers: `grep emit(` across src/ — none; equivalent
  coverage via `turn_battle_entity_snapshot` reconcile + `turn_cast_start` —
  the latter binds `CombatScene.onAttack`, a turn-presentation handler, not
  the legacy cast bar); `PhaserCanvas.seedRegion` no longer subscribes
  `positions` (the gate write + `battle_end`/`combat_scene_exit` clears
  retained as the standalone/legacy seam). Of the kept handlers only
  `onPositions` still has callers — `create()`'s
  `lastBattlePositionsSnapshot` fallback and the
  positionSmoothing/hudWiring/turnCountdownSpawn tests call it directly;
  `onCastStart`/`onCastComplete`/`onPlayerTeleported` are fully dead
  retained seams (parked for a future cleanup mission).
- **ARCH-012 (receipt-blind notifications).** Before: production toasted
  `+amount` and alchemy toasted `x pills` — the rolled/generated figures —
  while the bag clamp silently discarded the rest; collect-quest progress
  already counted delivered only, so UI contradicted quest. After: production
  computes `delivered = amount - overflow`, toasts `+delivered` (skipped when
  0), and pushes `createBagOverflowEvent(name, overflow)` for the lost part;
  alchemy toasts `x event.delivered` (skipped when 0), pushes
  `createBagOverflowEvent(name, event.overflow)`, and keeps the failure toast
  for `success:false` jobs. No grant paths changed; only the notification
  adapter consumes the receipt fields.

## Review round 1

Task review verdict: SPEC compliant / changes-needed — one Important + minors,
fixed in one scoped round (same branch, uncommitted).

1. **Important — non-stage `startBattle()` inherited the terminal once-guard**
   (correctness). `GameManagerTurnBattleOps.startBattle()` now calls
   `this.rewardOps.resetRewardState()` in its reset-defaults block. Before this
   fix a non-stage battle (devtools `enemySpawnDebug.spawnEnemy`, tribulation
   `launchBattle`) started after any terminal inherited `battleEndEmitted=true`:
   its victory/defeat never published `battle_end` (the exact ARCH-014
   starvation) AND a later `abandonBattle()` was silently swallowed by
   `emitAbandonEnd`'s guard — a regression vs the pre-M12 unconditional emit.
   `startBattleWithPlayer()` routes through `startBattle()` (verified:
   `stageWaves.launchBattle -> startBattleWithPlayer -> startBattle`), so one
   reset site covers every entry; `startStage` and `restartTurnBattleCycle`
   re-reset as before (idempotent). Regression coverage: two new tests in
   `GameManager.battleEndPublication.test.ts` — stage victory -> non-stage
   `startBattleWithPlayer` -> second victory emits once; stage victory ->
   direct `startBattle(CombatEntity)` -> abandon publishes defeat once.
2. **Stale `abandonBattle` doc** (`GameManager.ts`) — claimed the method emits
   `battle_end` itself "giống hệt BattleSystem.checkBattleEnd()"; corrected to
   describe routing through `rewardOps.emitAbandonEnd()` under the shared
   once-guard (kept Vietnamese per the file's comment convention; meaning
   fixed).
3. **G5 doc/comment nits** — the ledger line implied `turn_cast_start` drives
   CombatCastBar; it actually binds `CombatScene.onAttack` (a turn
   presentation handler). And "snapshot tests call them directly" held only
   for `onPositions` — `onCastStart`/`onCastComplete`/`onPlayerTeleported`
   have zero callers and are now recorded as fully-dead retained seams in
   both this report and the `getCombatEventBindings` comment in
   `CombatScene.ts`.
