# Fixpoint wave 4 — COR audit (0afd0b2f)

Correctness re-audit of the wave-3 delta on `codex/hoa-cau-fireball-vfx` @
`0afd0b2f`: the `_check_save_payload` boundary mirror
(`202610050002_beta_save_boundary_mirror.sql`), the App.vue live-rejection
routing, and the touched fixtures. Attack brief: does the mirror overshoot
(reject a payload a real client writer can legitimately produce), and do the
new checks hold on jsonb type edges.

Method: every SQL claim was executed — the wave-3 `create or replace
function` bodies were loaded verbatim into `postgres:16-alpine`
(`lc_ctype = en_US.utf8`) with stub tables and driven with adversarial
payloads; every client-side claim was traced to source. Pin tests added
under `game/tests/` (see foot of report).

## Findings

| ID | Severity | Finding |

| W4-COR-1 | **High** | **`player.nodeLevels` present-but-not-an-object escapes the mirror's reject contract as an unhandled Postgres exception → durable journal wedge, no recovery surface.** `202610050002_beta_save_boundary_mirror.sql:237` runs `jsonb_each(coalesce(p_payload->'player'->'nodeLevels', '{}'::jsonb))`. `coalesce` only rescues SQL NULL (absent key); a jsonb `null`, string, number, bool or array value passes straight through and `jsonb_each` raises `ERROR: cannot call jsonb_each on a non-object`. Executed repro (all four variants → same error; `"nodeLevels":[1,2]` crashes too — earlier assumption that arrays slip through was wrong). The exception propagates out of `write_character_save` → PostgREST error → `mapError` → `unavailable('SERVER_ERROR', retryable:false)` (`SupabaseCloudSaveService.ts:218-247,949-970`). Consequence chain is the wedge the mirror exists to kill: only a structured `REJECTED` clears/quarantines the pending journal record (`SupabaseCloudSaveService.ts:952-953`, `reconcilePendingSave.ts:56-59`); `unavailable` maps to `retry-same`, so the record replays the identical crashing payload on every later load. On the authority side `authorityStateForError('SERVER_ERROR') → 'reconnecting'` (`OnlineSessionController.ts:112-128`) — pause + retry forever, never terminal, never quarantined, never surfaced. Contrast: the intended path is SAVE_INVALID → quarantine → `SaveIncompatibleScreen` export/delete. Client truth for this class: `validateGameSaveShape` requires `isObject(player.nodeLevels)` (`saveShapeValidation.ts:1836`), so every non-object `nodeLevels` is unconditionally invalid — the mirror must reject it cleanly, not crash. The `jsonb_each` is new in wave-3 (grep: no earlier `_check_save_payload` iterates it). Fix direction: either type-guard `nodeLevels` to object before iterating (reject non-object outright — it is always invalid), or probe the five known root keys via `->>` casts (the check only ever reads five keys). Note the same input is also dangerous at :244 (`->'nodeLevels'->'hoa_linh_ngo'`) — `->` on a scalar returns NULL safely on pg16, so :237 is the only crash site, but a type-guard fix covers both. |
| W4-COR-2 | **Medium** | **`create_character` charset mirror rejects names a real client can legitimately produce** — overshoot on two Unicode classes. Client validator: `/^[\p{L}\p{N} _-]{2,20}$/u` on `value.trim()` (`CharacterCreationService.ts:45-47`); `\p{N}` = Nd+Nl+No and JS `trim()` strips all Unicode whitespace. The mirror (`:307-310`) uses Postgres `[[:alnum:]]` + `trim()`. Executed on `en_US.utf8`: `'Nguyễn Văn'` pass, `'AⅫ B'` (Nl roman numeral) pass, **`'A½ B'` (No, fraction) FAIL**, **`'Minh'` padded with NBSP FAIL**, tab/newline-padded names FAIL (Postgres `trim()` strips ASCII space only; NBSP is not `[[:alnum:]]`). Reachability: the client sends raw `draft.name` untrimmed (`SupabaseCharacterCreationService.ts:104`), so NBSP/tab padding and `No`-category digits are genuinely producible inputs, and the reject lands as `CHARACTER_NAME_UNAVAILABLE` — the client renders "name taken" for a charset failure, and `is_character_name_available` (`202608240001`) checks uniqueness only, so the availability probe says "free" moments before create rejects. **Deployment caveat (unverified):** `[:alnum:]` is locale-dependent — under `C`/`C.UTF-8` collation it is ASCII-only and every non-ASCII (i.e. Vietnamese) name fails; the executed result assumes the prod DB runs a UTF-8-aware ctype. Verify prod `datctype` before adjudicating severity: if prod is `C`/`C.UTF-8` this is Critical, not Medium. |

What the user actually sees is the generic authority terminal overlay (`authority.recovery` + re-auth, `:1245-1262`); convergence exists only via acknowledge → re-auth → boot → the same restore reject on the boot path (`useAppLifecycle.ts:447-459`) → `boot.fail()` → surface finally mounts. So the stated intent ("routes to saveIssue corrupted surface") is half-delivered: the record is written, nothing renders it, and the eventual surface requires a full re-auth round trip. Two sub-issues: (a) `saveIssue.clear()` has zero callers — if the remote row is repaired server-side before re-auth, boot succeeds and the stale `'corrupted'` status lingers for the renderer session; any *unrelated* later `entryStage === 'error'` failure renders `SaveIncompatibleScreen` with the stale record instead of the real boot error (`:1179` fires on status alone). ## Verified holds (no defect found)

- **No mirror overshoot on producible writes.** Every beta client save path was checked against each new check: creation-mortal (no pair, no receipts — passes), initiation-qi_refining (pair + fire + `five_elements_art` + grade ≥ 1 — passes), foundation (victory record non-empty — passes), respec/dev-reset (element commits only via `selectSpellPathElement`, which is mortal-only *and* `isBetaElement`-gated, `GameManagerProgressionOps.ts:550,569` — a non-fire committed element is unproducible, so F-SCOPE-1 cannot overshoot), and `pendingTalentEntitlement` flows (real writers always stamp `realmId = current realm`, which is always in-catalog — the catalog gate is a strict superset of producible values). The only true overshoot is W4-COR-2 (charset).
- **Realm catalog + ceiling parity.** The SQL `CASE` order (:109-120) equals `REALMS` array order exactly (`realm.ts`), and `getRealmIndex` is `REALMS.findIndex` (`realmSystem.ts:98-99`) — identical indices. `v_realm_index > 2` ≡ `isBeyondReleaseCeiling` (`progressionCeilingRealmId = 'foundation_establishment'`, `ReleasePolicy.ts:42`).
- **F-SCOPE-1 mirror is exact.** Committed pair (`spell`/`spell_pathway`) + `v_realm_index >= 1` ≡ client's `realmId !== 'mortal'` (unknown realms reject earlier, so all reachable realms are in-catalog); `spellPath.element = 'fire'` ≡ `getActiveElement` reading the same field (`CultivationPathSystem.ts:263-268`); `hoa_cau_thuat` in `skills` ≡ kit coherence `SPELL_KIT_IDS['fire'][0]` (`Skills.ts:23-24`). Skills non-object entries: `jsonb_typeof(s.v) = 'object'` guard mirrors client's `entry.id` reads — parity.
- **Mortal pair gate parity.** `v_realm_index = 0 and (player ? 'cultivationPath' or 'cultivationWay')` ≡ client's `mortal && hasPath` plus pair-coherence — key-presence semantics on both sides; way-only-on-mortal rejects on both (client via `hasPath !== hasWay`, server via `? 'cultivationWay'`).
- **Realm witness receipts parity.** `jsonb_array_length(techniques) < 1` (techniques is in `v_required_arrays`, type-guarded at :73-77 before the length call) ≡ client non-empty requirement; `breakthroughGrade` non-number or `< 1` → clean `SAVE_INVALID` — executed: `"abc"`, `0`, missing all reject correctly; the `is distinct from 'number'` typeof guard prevents cast crashes in practice. `highestFoundationAchieved` parity for missing/null/`''` (both layers reject).
- **jsonb type edges — clean except nodeLevels.** Executed on pg16: `->>`/`->` on scalar jsonb → NULL (no error), so `spellPath: 5`/`"x"`/`[1]` all reject cleanly at :224; `jsonb_array_elements_text` on object elements returns their text (`{"a": 1}`), which then dies at the non-string check :175-181 — the wave-2 W3-COR-2 coercion hole is closed. `selectedTalentIds`/`skills`/`techniques` are all `v_required_arrays` or explicitly typeof-guarded before `jsonb_array_elements*`/`jsonb_array_length` touch them.
- **Talent catalogs byte-exact.** `v_creation_catalog` = `CHARACTER_CREATION_TALENTS` (19 ids incl. `pham_cot`); `v_parked_talents` = `PARKED_TALENTS` (`tran_tam`, `phu_van`); `GREAT_DAO_REWARD_TALENTS` is the singleton `pham_nhan_chi_cot` (so the single-id witness check is complete); `v_pool_min_realm` = all 13 `BREAKTHROUGH_TALENT_POOLS` ids at the correct realm indices; `CHARACTER_CREATION_TALENT_COUNT = 1` matches the `1 +` ceiling constant.
- **`characters.realm_id` normalization is safe.** Column is informational — the payload's `player.realmId` is authoritative; the only reader found is `create_character`'s own response field (`:332`). `default 'mortal'` + the `'pham_nhan'` update align it with the client catalog; no CHECK constraint exists to conflict.
- **`attemptReconnect` plumbing.** `outcome.save` is a normalized `GameSave`; `lineage === 'same'` carries `save: undefined` so the rejected-branch guard (`lineage === 'replaced' && save`) is correct; local-only mode calls `onResume('same')` and skips restore entirely. `markFailed('recovery')` → `enterTerminal` → generation bump + clearHeartbeat/clearRetry + `onPause('terminal')` → `pauseSimulation` — the "sim must not run on an unconsumable payload" semantics hold.
- **`highestFoundationAchieved` values.** `FOUNDATION_LABELS` = {human, earth, heaven, great_dao}; fixture's `'human'` is catalog-valid.
